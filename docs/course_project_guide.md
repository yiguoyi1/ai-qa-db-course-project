# 课程项目展示指南

问知社区 AskWise Community 是一个数据库课程设计与全栈应用开发项目。项目以问答社区为业务场景，将关系数据建模、数据库编程、HTTP 接口和多端界面连接起来。

## 项目要解决的问题

用户可以围绕学习、生活、技术等领域发布问题，由其他用户或 AI 提供回答。回答可以被采纳、评价和讨论，浏览、收藏等行为又用于构建兴趣画像与推荐问题。AI 首答、多轮追问、自动分类和自动标签均通过 DeepSeek API 实现。

Web 页面、Tauri 桌面客户端和独立 CLI 共用 FastAPI 后端。桌面端通过 WebView 访问现有网页，CLI 通过 HTTP 调用接口；业务数据统一保存在 Oracle 中。

## 建议展示顺序

| 环节 | 演示操作 | 说明重点 |
| --- | --- | --- |
| 1. 产品入口 | 打开 `/`，再进入 `/home` | 项目定位、游客浏览、分类与标签筛选 |
| 2. 发布问题 | 注册登录，发布带分类、标签的问题 | 用户身份校验、问题持久化、AI 首答可选 |
| 3. 社区互助 | 使用另一个账号回答、评论，提问者采纳答案 | 用户间交流、楼中楼、作者权限和采纳归属 |
| 4. AI 追问 | 围绕 AI 首答创建并续写会话 | 问题与首答绑定、上下文存储、会话续写权限 |
| 5. 兴趣推荐 | 浏览、收藏后，在用户中心重建画像、刷新推荐 | 行为记录、时间衰减、兴趣权重与推荐理由 |
| 6. 数据库验证 | 查看表结构、视图和过程，删除一条自己的回答后检查数量 | 数据库对象服务于实际业务，软删除与统计一致 |
| 7. 管理治理 | 使用管理员账号查看用户、内容与日志 | 权限隔离、内容状态管理和操作审计 |

演示需要运行中的 Oracle 和 FastAPI。AI 相关操作还需要有效的 DeepSeek API Key。可以先使用纯社区发帖验证人工问答，再展示 AI 能力。

## 值得讲清楚的实现选择

**数据库承担业务约束。** 关系、状态和值域约束直接落在 SQL 中，触发器和过程维护冗余统计，避免展示数量与明细长期不一致。

**AI 参与社区流程。** 用户可以选择人工交流或 AI 首答，追问会话绑定问题和 AI 回答；系统记录提示词、响应和调用信息，便于追溯。

**推荐有可解释的依据。** 标签画像结合提问、回答、浏览、收藏、反馈、评论和搜索等行为；排序综合兴趣、相似兴趣用户、热度、新鲜度和惩罚项。当前实现不包含训练好的深度学习推荐模型。

**多端共用业务接口。** `api` 处理请求与权限，`services` 编排业务，`repositories` 访问 Oracle，`integrations/llm` 封装模型调用。前端只通过 API 参与业务。

## 测试与演示准备

按照 [首页快速开始](../README.md#quick-start) 初始化环境，注册至少两个普通账号。需要管理员演示时，使用已有的 [管理员授权与治理流程](admin_governance_guide.md)。

```powershell
# 需 Docker / Oracle；创建临时校验 schema，结束后清理
powershell -ExecutionPolicy Bypass -File .\scripts\validate-oracle-schema.ps1

# 需应用 schema 和演示数据；使用 fake LLM，不消耗真实 API 额度
.\.venv\Scripts\python.exe -B .\scripts\validate_chat_followup.py
```

功能测试范围和操作步骤见 [测试指南](testing_guide.md)，详细用例见 [测试计划与用例](qa_test_plan_and_cases.md)。测试脚本可用不等于当前部署已经通过测试；演示前应在实际环境执行并记录结果。

## 展示边界

当前版本用于课程展示和学习交流。评论配图、通知、媒体审核和更完整的推荐运营能力仍有扩展空间；已有实现与后续事项见 [当前状态](current_status.md)。

首页截图取自仓库中的产品介绍页；该页面的社区卡片属于原有静态产品示意。数据库结构、接口能力和测试范围以源代码与测试结果为依据。
