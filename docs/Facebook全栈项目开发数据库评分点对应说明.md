# Facebook 全栈项目开发数据库评分点对应说明

> 本文档根据课程评分标准整理，说明当前项目的业务功能和数据库设计分别体现在哪些真实目录、代码文件和 SQL 脚本中。文档只基于当前仓库真实实现，不把未实现内容写成已实现。

## 一、项目和数据库总体体现位置

当前项目是一个以 AI 问答社区为核心的全栈系统。前端、后端和数据库并不是分离的孤立作业，而是通过真实业务流程串联起来：

```text
用户在前端页面操作
        ↓
JavaScript 调用 FastAPI 接口
        ↓
后端 Service 做业务校验和事务控制
        ↓
Repository 执行 Oracle SQL
        ↓
Oracle 数据库存储用户、问题、回答、评论、收藏、推荐、日志、图片等数据
        ↓
后端返回 JSON 或图片二进制
        ↓
前端重新渲染页面
```

核心体现位置如下：

| 层次 | 体现位置 | 说明 |
|---|---|---|
| 前端页面 | `app/web/` | 首页、登录、社区首页、详情、用户中心、后台页面 |
| 后端接口 | `app/api/routes/` | 注册登录、问题、回答、评论、收藏、推荐、媒体、管理员接口 |
| 业务逻辑 | `app/services/` | 处理发帖、AI 首答、评论、点赞、推荐、上传、权限等业务 |
| 数据库访问 | `app/repositories/` | 执行 Oracle SQL，操作真实数据库表 |
| 数据库设计 | `sql/create_tables.sql` | 建表、主键、外键、检查约束、索引、大对象字段 |
| 数据库过程 | `sql/procedures.sql` | 统计同步、画像重建、推荐生成 |
| 数据库触发器 | `sql/triggers.sql` | 自动维护统计字段和登录时间 |
| 数据库视图 | `sql/views.sql` | 问题概览、热榜、回答质量、用户画像、推荐明细等 |
| 数据迁移 | `sql/migrations/` | 旧库升级、新增功能、优化索引、刷新视图 |
| 演示数据 | `sql/seed_data.sql` | 用于课堂演示和功能测试 |

答辩时可以这样说：

> 我们的项目不是只写了页面，也不是只写了数据库脚本。用户在页面上发帖、评论、收藏、上传图片，最终都会落到 Oracle 数据库的对应表中；数据库中的表、约束、索引、视图、触发器和过程，也都被后端代码真实调用。

## 五、表空间体现在哪里

### 5.1 当前真实情况

当前项目没有单独编写：

```sql
CREATE TABLESPACE ...
```

也没有在建表语句中显式指定：

```sql
TABLESPACE xxx
```

项目目前使用 Oracle 容器中的应用用户/schema：

- `APP_USER`
- 默认示例值：`AI_QA_APP`

配置位置：

```text
.env.example
compose.yaml
docker/oracle/startup/01-create-app-user.sh
app/core/settings.py
```

### 5.2 答辩建议说法

答辩时可以这样说：

> 当前项目重点实现了 schema 级的数据表、约束、索引、视图、触发器和过程，没有单独创建表空间。表空间这一项如果老师要求，可以后续扩展，在 Oracle 中为项目创建独立表空间，并把 `AI_QA_APP` 用户的数据对象指定到该表空间。

### 5.3 如果后续补充表空间，可以这样设计

示例，不代表当前已实现：

```sql
CREATE TABLESPACE ai_qa_data
DATAFILE 'ai_qa_data01.dbf'
SIZE 200M
AUTOEXTEND ON NEXT 50M MAXSIZE 2G;

ALTER USER AI_QA_APP
DEFAULT TABLESPACE ai_qa_data;
```

注意：以上是后续可扩展方案，当前项目未实现。

## 六、主键和外键体现在哪里

### 6.1 主键

主键在 `sql/create_tables.sql` 中大量体现，例如：

```sql
CONSTRAINT pk_users PRIMARY KEY (user_id)
CONSTRAINT pk_questions PRIMARY KEY (question_id)
CONSTRAINT pk_answers PRIMARY KEY (answer_id)
CONSTRAINT pk_answer_comments PRIMARY KEY (comment_id)
```

主键作用：

- 唯一标识每一条记录。
- 作为其他表外键引用目标。
- 提高按 ID 查询效率。

### 6.2 外键

外键也在 `sql/create_tables.sql` 中体现，例如：

| 外键关系 | 业务含义 |
|---|---|
| `questions.user_id -> users.user_id` | 一个用户可以发布多个问题 |
| `questions.category_id -> categories.category_id` | 一个问题属于一个分类 |
| `answers.question_id -> questions.question_id` | 一个问题可以有多个回答 |
| `answers.user_id -> users.user_id` | 人工回答属于某个用户 |
| `question_tags.question_id -> questions.question_id` | 标签绑定到问题 |
| `question_tags.tag_id -> tags.tag_id` | 问题关联标签 |
| `favorites.user_id -> users.user_id` | 收藏属于用户 |
| `favorites.question_id -> questions.question_id` | 收藏指向问题 |
| `answer_comments.parent_comment_id -> answer_comments.comment_id` | 评论楼中楼自引用 |
| `recommendations.user_id -> users.user_id` | 推荐结果属于用户 |
| `recommendations.question_id -> questions.question_id` | 推荐结果指向问题 |

答辩时可以这样说：

> 主键保证每张表的数据唯一，外键保证表之间引用合法。例如回答必须属于一个真实存在的问题，收藏必须属于真实用户和真实问题，这些都通过外键约束保证。

## 九、序列体现在哪里

### 9.1 当前真实实现

当前项目没有单独写：

```sql
CREATE SEQUENCE ...
```

但是大量主键使用了 Oracle Identity 自增列：

```sql
user_id NUMBER GENERATED BY DEFAULT ON NULL AS IDENTITY
question_id NUMBER GENERATED BY DEFAULT ON NULL AS IDENTITY
answer_id NUMBER GENERATED BY DEFAULT ON NULL AS IDENTITY
```

出现位置：

```text
sql/create_tables.sql
```

涉及表：

- `users`
- `categories`
- `tags`
- `media_assets`
- `questions`
- `answers`
- `question_tags`
- `answer_feedback`
- `answer_comments`
- `favorites`
- `browse_history`
- `search_history`
- `recommendations`
- `user_tag_profile`
- `chat_session`
- `chat_message`
- `ai_prompt_log`
- `login_log`
- `operation_log`

### 9.2 答辩建议说法

答辩时可以这样说：

> 当前项目没有显式创建序列，而是使用 Oracle 的 Identity 自增列。Identity 底层本质上也是由数据库维护自增值，效果上相当于为主键提供自动编号。这样写法更简洁，也减少了手动维护序列和触发器的复杂度。

## 十一、过程和函数体现在哪里

过程和函数定义在：

```text
sql/procedures.sql
```

项目使用了 Oracle PL/SQL 包：

```sql
CREATE OR REPLACE PACKAGE qa_app_pkg AS
```

包中包含：

| 名称 | 类型 | 作用 |
|---|---|---|
| `sync_question_statistics` | 过程 | 同步问题浏览数、收藏数、回答数 |
| `refresh_answer_feedback_stats` | 过程 | 同步回答点赞、点踩、平均评分 |
| `rebuild_user_tag_profile` | 过程 | 根据用户行为重建标签画像 |
| `get_recommendation_score` | 函数 | 计算某用户对某问题的推荐分 |
| `generate_recommendations` | 过程 | 生成用户推荐问题 |

后端调用位置：

| 数据库过程 | 后端调用文件 |
|---|---|
| `rebuild_user_tag_profile` | `app/repositories/recommendation_repository.py` |
| `generate_recommendations` | `app/repositories/recommendation_repository.py` |
| `sync_question_statistics` | 由触发器调用 |
| `refresh_answer_feedback_stats` | 由触发器调用 |

答辩时可以这样说：

> 过程和函数主要用于靠近数据库的数据计算，比如推荐和统计。把这些逻辑放到 PL/SQL 包中，可以减少后端重复计算，也能让数据库直接处理多表聚合。

## 十二、大对象体现在哪里

## 十四、数据库评分点背诵版

### 14.1 30 秒版本

> 我们项目的数据库主要体现在 `sql/` 目录中。`create_tables.sql` 定义了用户、问题、回答、评论、收藏、推荐、媒体、日志等核心表，并设置了主键、外键、唯一约束、检查约束和索引。`views.sql` 定义了问题概览、热榜、用户活动、推荐明细等视图。`triggers.sql` 用触发器自动维护统计字段和登录时间。`procedures.sql` 用 PL/SQL 包实现用户画像和推荐生成。项目还使用 CLOB 保存长文本，BLOB 保存图片，数据库设计和前后端功能是对应起来的。

### 14.2 1 分钟版本

> 数据库设计在项目中体现得比较完整。首先，业务对象都有对应表，比如 `users` 对应用户，`questions` 对应问题或动态，`answers` 对应回答，`answer_comments` 对应评论楼中楼，`favorites` 对应收藏，`answer_feedback` 对应点赞点踩，`media_assets` 对应图片。其次，表之间通过外键建立关系，比如问题属于用户，回答属于问题，评论属于回答，问题和标签通过 `question_tags` 实现多对多。再往下，项目还建立了索引提高查询效率，建立视图简化统计展示，用触发器自动同步统计字段，用过程和函数实现画像和推荐。当前没有单独创建表空间，也没有显式 `CREATE SEQUENCE`，而是使用 Oracle Identity 自增列。

## 十六、老师可能追问的问题

Q1：你们项目的数据表体现在哪里？  
A1：主要在 `sql/create_tables.sql`。里面定义了 `users`、`questions`、`answers`、`answer_comments`、`favorites`、`recommendations`、`media_assets` 等核心表，覆盖了用户、内容、互动、推荐、媒体和日志。

Q2：用户体现在哪里？  
A2：数据库里有 `users` 表，后端有 `AuthService` 和 `auth_deps.py` 负责注册登录和 JWT 鉴权，前端有 `login.html` 和 `profile.html` 负责登录和用户中心。

Q3：你们有没有表空间？  
A3：当前没有单独创建表空间，使用的是 Oracle 应用用户的默认表空间。后续如果按生产或课程要求细化，可以增加 `CREATE TABLESPACE` 并把项目用户默认表空间指定过去。

Q4：你们有没有序列？  
A4：没有显式 `CREATE SEQUENCE`，但主键使用了 Oracle 的 `GENERATED BY DEFAULT ON NULL AS IDENTITY` 自增列。它由数据库自动维护编号，效果上满足主键自动生成。

Q5：你们的大对象体现在哪里？  
A5：问题正文、回答正文、评论、AI prompt 用 CLOB；图片用 `media_assets.file_content BLOB` 保存。头像、问题图、回答图都通过媒体接口写入数据库 BLOB。

Q6：触发器有什么实际作用？  
A6：触发器用于自动维护统计字段。比如新增收藏后同步问题收藏数，新增浏览后同步浏览数，回答反馈变化后同步点赞数和平均评分，登录成功后同步用户最近登录时间。

Q7：过程和函数有什么实际作用？  
A7：`qa_app_pkg` 包中有同步统计、刷新回答反馈统计、重建用户标签画像、计算推荐分、生成推荐等过程和函数。推荐系统就是通过这些 PL/SQL 逻辑落地的。

Q8：视图有什么实际作用？  
A8：视图封装复杂查询，比如 `v_question_overview` 聚合问题、用户、分类、标签和图片统计；`v_user_activity_summary` 汇总用户活动；`v_active_recommendation_detail` 展示推荐明细。

Q9：索引为什么重要？  
A9：项目有问题列表、搜索、用户中心、推荐、日志查询等高频查询。索引能减少全表扫描，提高按用户、状态、分类、时间、标签查询的效率。

Q10：数据库和前端功能怎么对应？  
A10：比如用户在首页发帖，前端调用 `/api/questions`，后端写 `questions` 和 `question_tags`；用户评论时写 `answer_comments`；收藏写 `favorites`；上传图片写 `media_assets`。所以页面操作都有数据库落点。
