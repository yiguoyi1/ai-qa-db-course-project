# 业务数据流设计

## 1. 总体说明

本系统的数据流围绕“提问 - 回答 - 行为 - 画像 - 推荐”展开，目标是让每一次用户操作都能沉淀为可追踪、可统计、可用于推荐的数据。

总体链路如下：

```text
登录/进入系统
    ↓
提问 / 浏览 / 搜索 / 收藏 / 反馈
    ↓
行为数据写入业务表
    ↓
触发器与过程更新统计字段
    ↓
重建用户标签画像
    ↓
生成个性化推荐
```

## 2. 登录数据流

### 2.1 业务目标

- 记录每次登录尝试结果
- 区分成功、失败和锁定状态
- 在成功登录时更新用户最近登录时间

### 2.2 数据流步骤

1. 用户提交账号和密码
2. 应用层完成认证判断
3. 写入 `LOGIN_LOG`
4. 当 `RESULT = 'SUCCESS'` 时，触发器自动更新 `USERS.LAST_LOGIN_TIME`

### 2.3 涉及数据表

- `USERS`
- `LOGIN_LOG`

## 3. 提问与回答数据流

### 3.1 业务目标

- 保存用户提出的问题
- 记录 AI 或人工回答
- 自动维护问题回答数

### 3.2 数据流步骤

1. 用户提交问题标题、正文、分类
2. 系统写入 `QUESTIONS`
3. 系统根据标签策略写入 `QUESTION_TAGS`
4. 若为 AI 回答，写入 `ANSWERS`，同时记录 `AI_PROMPT_LOG`
5. 若为人工补充，也写入 `ANSWERS`
6. 回答表发生变化后，触发器调用过程同步 `QUESTIONS.ANSWER_COUNT`

### 3.3 涉及数据表

- `QUESTIONS`
- `TAGS`
- `QUESTION_TAGS`
- `ANSWERS`
- `AI_PROMPT_LOG`

## 4. 浏览与收藏数据流

### 4.1 业务目标

- 记录用户对问题的访问行为
- 用真实行为驱动问题热度和用户画像

### 4.2 浏览数据流

1. 用户进入问题详情页
2. 系统记录 `BROWSE_HISTORY`
3. 触发器调用统计过程，重算问题浏览数

### 4.3 收藏数据流

1. 用户点击收藏
2. 系统写入 `FAVORITES`
3. 唯一约束保证同一用户不能重复收藏同一问题
4. 触发器调用统计过程，重算问题收藏数

### 4.4 涉及数据表

- `QUESTIONS`
- `BROWSE_HISTORY`
- `FAVORITES`

## 5. 回答反馈数据流

### 5.1 业务目标

- 记录用户对回答的质量评价
- 为回答排序和推荐提供质量信号

### 5.2 数据流步骤

1. 用户对回答执行点赞、点踩或评分
2. 系统写入或更新 `ANSWER_FEEDBACK`
3. 唯一约束保证同一用户对同一回答只保留一条当前反馈
4. 触发器调用过程，自动刷新：
   - `ANSWERS.LIKE_COUNT`
   - `ANSWERS.DISLIKE_COUNT`
   - `ANSWERS.AVG_RATING`

### 5.3 涉及数据表

- `ANSWERS`
- `ANSWER_FEEDBACK`

### 5.4 评论与回复数据流补充

1. 用户在某条回答下发表评论或回复已有评论
2. 系统写入 `ANSWER_COMMENTS`
3. 若为回复评论，则同步维护父评论的 `REPLY_COUNT`
4. 删除评论时采用软删除，仅更新评论状态和删除时间
5. 查询评论树时，已删除顶层评论显示“原评论已删除”，已删除回复显示“原回复已删除”

涉及数据表：

- `ANSWERS`
- `ANSWER_COMMENTS`

## 6. 搜索数据流

### 6.1 业务目标

- 留存用户搜索词，辅助后续推荐和热点分析

### 6.2 数据流步骤

1. 用户输入关键字执行搜索
2. 系统记录 `SEARCH_HISTORY`
3. 后续可基于高频关键词构建热点分析或搜索推荐

### 6.3 涉及数据表

- `SEARCH_HISTORY`

## 7. 用户画像数据流

### 7.1 业务目标

- 根据用户行为沉淀兴趣标签权重
- 让推荐不只依赖单次行为，而是反映用户整体偏好

### 7.2 权重来源

- 用户自己发布的问题标签
- 用户收藏的问题标签
- 用户浏览的问题标签
- 用户反馈过的回答所关联的问题标签

### 7.3 数据流步骤

1. 系统读取用户行为数据
2. 存储过程 `rebuild_user_tag_profile` 汇总不同来源的标签权重
3. 删除旧画像后重建 `USER_TAG_PROFILE`

### 7.4 涉及数据表

- `QUESTIONS`
- `QUESTION_TAGS`
- `FAVORITES`
- `BROWSE_HISTORY`
- `ANSWER_FEEDBACK`
- `USER_TAG_PROFILE`

## 8. 推荐生成数据流

### 8.1 业务目标

- 基于用户画像为用户推荐其可能感兴趣的问题

### 8.2 当前实现逻辑

当前版本实际落地的是基于标签画像的推荐流程：

1. 先将当前用户已有的 `TAG_BASED` 活跃推荐置为 `EXPIRED`
2. 从 `QUESTIONS` 中筛选候选问题
3. 过滤用户自己提问的问题
4. 过滤用户已经收藏的问题
5. 过滤非 `OPEN` 状态的问题
6. 计算推荐分数
7. 取前 N 条写入 `RECOMMENDATIONS`

### 8.3 涉及数据表

- `QUESTIONS`
- `QUESTION_TAGS`
- `USER_TAG_PROFILE`
- `RECOMMENDATIONS`
- `FAVORITES`

## 9. 多轮对话数据流

### 9.1 业务目标

- 保留用户与 AI 的连续交流上下文
- 支撑问题追问和历史会话回放

### 9.2 数据流步骤

1. 用户发起一轮新会话，创建 `CHAT_SESSION`
2. 用户消息写入 `CHAT_MESSAGE`
3. AI 回复同样写入 `CHAT_MESSAGE`
4. 会话结束时更新 `CHAT_SESSION.END_TIME` 和 `STATUS`

### 9.3 涉及数据表

- `CHAT_SESSION`
- `CHAT_MESSAGE`

## 10. 操作审计数据流

### 10.1 业务目标

- 记录系统关键行为和管理动作
- 为问题排查和后台审计提供数据依据

### 10.2 数据流步骤

1. 用户或管理员执行关键操作
2. 系统写入 `OPERATION_LOG`
3. 后续可按用户、时间或操作类型追踪行为

### 10.3 涉及数据表

- `OPERATION_LOG`

## 11. 当前版本的数据流特点

- 数据流闭环完整，已经覆盖主链路
- 关键统计不是前端临时算，而是由数据库过程和触发器维护
- 推荐链路已经可运行，但当前实现仍以标签推荐为主
- 社区评论、楼中楼回复、采纳答案与用户中心已经纳入主业务流
- 日志链路比较完整，适合做课程设计展示和答辩说明

## 12. 管理员治理数据流补充

### 12.1 角色校验流

1. 管理员发起后台治理请求。
2. 系统解析 JWT，获取当前登录用户身份。
3. 后端读取 `USERS`，确认当前用户状态为 `ACTIVE` 且 `ROLE = 'ADMIN'`。
4. 校验通过后进入对应治理服务。

涉及数据表：

- `USERS`

### 12.2 用户治理流

1. 管理员查询用户列表。
2. 系统按角色或状态筛选 `USERS`。
3. 管理员决定修改某个用户的角色或状态。
4. 系统校验保护规则：
   - 不能移除自己的管理员身份
   - 不能停用自己当前账号
   - 最后一个有效管理员必须保留
5. 更新 `USERS`
6. 写入 `OPERATION_LOG`

涉及数据表：

- `USERS`
- `OPERATION_LOG`

### 12.3 问题治理流

1. 管理员定位目标问题。
2. 网页后台可通过最近问题列表查看问题 ID，并一键填入治理表单。
3. 系统读取 `QUESTIONS` 当前状态。
4. 管理员执行状态调整，例如 `CLOSED` 或 `ARCHIVED`。
5. 系统更新 `QUESTIONS.STATUS`。
6. 写入 `OPERATION_LOG`。

涉及数据表：

- `QUESTIONS`
- `OPERATION_LOG`

### 12.4 评论治理流

1. 管理员定位回答评论或回复。
2. 网页后台可先选择问题，再展开回答读取该回答下的评论 ID。
3. 系统读取 `ANSWER_COMMENTS` 当前状态。
4. 管理员执行 `HIDDEN` 或恢复为 `ACTIVE`。
5. 系统更新 `ANSWER_COMMENTS.STATUS`，并刷新 `UPDATE_TIME`。
6. 评论查询时若状态为 `HIDDEN`，则以“已被管理员隐藏”的占位内容返回。
7. 写入 `OPERATION_LOG`。

涉及数据表：

- `ANSWER_COMMENTS`
- `OPERATION_LOG`

### 12.5 分类管理流

1. 管理员查看当前分类列表，可按状态筛选。
2. 管理员创建新分类，或修改已有分类的名称、描述和状态。
3. 系统更新 `CATEGORIES`。
4. 写入 `OPERATION_LOG`。

涉及数据表：

- `CATEGORIES`
- `OPERATION_LOG`

### 12.6 日志查询流

1. 管理员发起登录日志或操作日志查询。
2. 系统按用户、结果或操作类型等条件筛选日志。
3. 系统返回分页结果，用于后台审计和问题排查。

涉及数据表：

- `LOGIN_LOG`
- `OPERATION_LOG`
- `USERS`

### 12.7 当前实现边界说明

- 管理员当前版本已实现的是“基础治理链路 + 网页后台交互”，不是覆盖媒体审核和推荐规则干预的完整后台管理系统。
- 当前已经具备分类管理、用户治理、问题治理、评论治理以及日志查询能力。
- 当前尚未实现推荐规则治理和媒体审核接口。
